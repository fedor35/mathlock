# Режим «Чтение вслух»

Ребёнок читает текст вслух, чтобы разблокировать телефон. Всё работает без интернета.

## Конвейер

```
микрофон 16 кГц → фронтенд (лог-мел / сырой звук) → CTC-модель (NPU или CPU) → жадный декодер
   → ReadingMatcher (буквенное выравнивание с текстом, по словам: OK / ОШИБКА / ещё не прочитано)
   → подсветка слов на экране; все слова OK → разблокировка
```

Модули: `android/reading` (движок, без UI), `android/readbench` (стенд замеров, отдельный пакет — без блокировки),
`android/app` («Таблица»: задание чтения на экране блокировки — раздел «В «Таблице»»),
`ml/` (экспорт, квантование, озвучка, фикстуры). Тексты: `content/<язык>/texts.jsonl`.

## Переключаемость языков и моделей

Два независимых слоя:

* `LanguageSpec` — правила языка: алфавит, гласные, нормализация букв (ё→е), «похожие» пары, которые не считаются
  ошибкой чтения (безударные а/о, оглушение), слогораздел для отображения. Есть `ru`, черновик `kk`.
* `AsrModelSpec` — манифест модели `*.model.json` рядом с `.onnx`: языки, единицы (`letters`/`phonemes`),
  фронтенд, словарь CTC, blank, файлы под CPU / HTP fp16 / HTP int (QDQ), окно статической формы.
  Модель меняется без правки кода; на язык может быть несколько моделей.

`ReadingMatcher` работает с «единицами сравнения»: на одной стороне `ReadingText.letters`, на другой выход модели.
Для фонетичной орфографии (ru, kk) это буквы. Для английского буквенная сверка плохая (spelling ≠ sound),
поэтому там нужна фонемная модель (wav2vec2-phoneme / MMS, espeak-IPA) и словарь/G2P для текста.

| Язык | Модель сейчас | План |
|---|---|---|
| ru | GigaAM-v3 `ctc` (символы, 240M, MIT) | дообучить на записях сына (детская речь) |
| kk | — | дообучить GigaAM-v3 с новой CTC-головой (42 буквы) на KSC2 (ISSAI) + детские записи |
| en | — | фонемная CTC (wav2vec2-xlsr-espeak / MMS) + CMUdict; либо Parakeet-CTC по буквам с G2P-сверкой |

## Сверка (ReadingMatcher)

Пробелы гипотезы игнорируются: при чтении по слогам ASR выдаёт «ма ма мы ла». Цены: вставка 0,35 (повторы слогов),
пропуск 1, пропуск последней буквы слова 1,6 (окончания), замена 1, «похожая» замена 0,4. Слово засчитано при
доле ошибок ≤ 0,25; однобуквенные и двубуквенные предлоги прощаются, если слова вокруг прочитаны.
Непрочитанный хвост бесплатен, поэтому подсветка идёт по ходу чтения.
На 36 клипах синтезированного детского чтения все решения верные (`FixtureTest`). Пороги будут подстраиваться на живых записях.

## Сверка на живых записях (05.11)

Первый вечер семьи: 40 засчитанных попыток, 2839 слов; опора — независимая расшифровка Whisper large-v3 (`ml/live_eval`).

- Красные у Фёдора на L9 (перечитывал фразы нарочно) — уже исправлены сверкой с перечитыванием от 04.11; остаток —
  проглоченная конечная «й» («дымко[й]»), теперь её пропуск стоит как обычный пропуск буквы.
- Окончания: у Вероники ~100 засчитанных слов, где телефон слышит другое окончание («жил» → «жили», «маленький» →
  «маленькие», «вдохнул» → «вдохнула»); Whisper подтверждает около 60%. Правило `endErr`: замена гласной/«й»/«м»/«х»/«в»
  в двух последних буквах (кроме аканья/иканья — похожих пар о/а, е/и, е/я, и/ы), пропуск конечной гласной, 1–2 лишние
  буквы сразу за словом — если это не начало следующего слова, не повтор хвоста и не отдельное слово после пробела CTC
  (заминка «Ерлан… а…»).
- Цена правила на правильной озвучке корпуса: ложных красных 0,27% → 0,63% (на L9 0,7% → 1,9% — безударные окончания
  распознавание путает и у диктора). Поэтому по умолчанию это **мягкая подсказка**: слово засчитано (зелёное), его
  окончание оранжевое жирное с подчёркиванием, под текстом «Оранжевым — проверь окончания»; в точность и уровень не
  идёт. `strictEndings = true` делает такие слова ошибкой — включать после дообучения на детской речи.

## Живые записи сына 05–10.11 и 0.4.2

55 записей с 13 Lite (до 07.11 — 0.3.x, после — 0.4.1 «красное — сразу перечитать»). Стенд — `ml/live_eval`:
`dump_logits.py` на r99950x считает лог-вероятности GigaAM окнами как в приложении, `Sim2` гоняет поток по ним
(шаг 400 мс, prev между записями одного текста, отпуск через 6 слов) и печатает каждую остановку с оценкой по звуку.

- **Остановки по делу.** Из ~70 остановок на 0.4.1 большинство на настоящих ошибках: «кругом» → «круглое»,
  «написала» → «нарисовала», «летит» → «летел», «улыбается» → «улыбнулся»; сын исправляет за 2–6 с.
- **Застревал** (до 0.4.2):
  - короткое слово не засчитывалось повтором (повтор ищется только у слов от 4 букв): «аул» 22 с, «ток» 17 с,
    «что» 16 с (7 повторов), «ещё» — до конца записи, «у» — сын начинал заново;
  - исправление сразу за словом «ещё в темно в темноте»: выравнивания одной цены, выбиралось то, где лишние буквы
    делят «ещё» на два коротких куска, оба штрафовались;
  - «поду» вместо «подул»: слово без последней буквы — «ещё читается», ни зелёного, ни красного;
  - три тычка в микрофон за 2 с оставили красным первое слово следующей попытки.
- **Распознавание теряет буквы, которые в звуке есть**: «ток» → «ок», «Ерлан» → «ерла», «солнце» → «соце»,
  «кулак» → «кукауак». У лучшего пути и у правильного слова почти одна вероятность.

**0.4.2:**

| что | как |
|---|---|
| вставка одним куском | у выравнивания отдельная надбавка 0,001 за начало вставки (Gotoh); матрица цен больше не хранится — только указатели |
| повтор короткого слова | красное слово 1–3 буквы засчитывается, если в 60 буквах дальше оно сказано отдельным словом (между пробелами CTC) |
| второе мнение по звуку | `WordScore`: Viterbi «что угодно — слово по CTC — пауза» на кадрах слова минус лучший путь, на букву; ≥ −0,4 — красное снимаем (только «по буквам не то», строгие окончания не трогает) |
| молчание 2 с | слово без одной последней буквы (от 4 букв) судим сразу; по слогам «при… цесса» — ждём |
| пустая первая запись | ни одного верного слова — «Не расслышал», красного не остаётся |

Порог звука выбран на записях сына: 1108 верно прочитанных слов (кусок речи = слово) — «соседняя» форма вместо
сказанной проходит: без последней буквы 2,2%, другая конечная гласная 0,4%, лишняя буква 0,3%, чужое слово 0%.
Пауза после слова обязательна — без неё короткая форма всегда находится в длинной (99,9%). Настоящие ошибки сына
дают −0,9…−7, спасённые слова — «ток» 0,0, «Ерлан» −0,06, «кулак» −0,14, «солнце» −0,32.

Итог по 33 записям 07–10.11: время на красном 307 → 157 с (без записи с разговором и Алисой). Эталонная озвучка
(`F`): ложных красных 0,27%, как было. Синтетические ошибки (`ml/synth_errors/GA.java`, гипотезы из тех же
лог-вероятностей): замены 79,3 → 78,9%, неверные окончания красным 14,0 → 12,7% (с подсказкой 43,6 → 43,3%),
пропуски 99,1%, соседние с ошибкой красные 1,1 → 1,0%, по слогам 2,8 → 2,5%.

Осталось: «аул» → «ау» — последней «л» нет и по звуку (−3,6), похоже, сын её глотает (и в «подул», «Ерлан»).

## Синтетические ошибки чтения (05.11)

Своих детских записей с размеченными ошибками мало, открытых русских наборов детского чтения с разметкой ошибок нет
(есть платный Nexdata — свободная речь до 12 лет, EmoChildRu — по запросу, RusLan-M — двое малышей). Поэтому ошибки
подставлены в тексты корпуса и озвучены (`ml/synth_errors`): 390 текстов × 2 варианта, ~1 ошибка на 7 слов, Silero
(5 голосов; половина сдвинута вверх ×1,15 как грубый «детский» голос), гипотеза GigaAM-v3 по кускам ≤ 220 символов.
Метки известны заранее, поэтому видно, что сверка ловит, а что прощает. 780 вариантов, 1877 подставленных окончаний.

| подставлено | красным | красным или с подсказкой окончания |
|---|---|---|
| пропуск слова (≥ 3 буквы) | 99,6% | 99,6% |
| другое похожее слово («лиса → липа») | 79% | 86% |
| неверное окончание («новую бусы») | 14% | 44% |
| повтор, фальстарт «ко… кошка», самоисправление «кошку… кошка» (должно быть зелёным) | 0–0,2% | ≤ 1% |
| по слогам «ма, ши, на» (должно быть зелёным) | 2,6% | 4,8% |
| верные слова рядом с ошибкой / далеко | 1,1% / 0,1% | 2,3% / 0,1% |

«Детский» сдвиг голоса почти ничего не меняет (окончания 41% против 48% у взрослых голосов).

- Окончания теряет в основном **распознавание**: 85% пропущенных — GigaAM вернул правильное слово. Он правит грамматику
  по соседям («у Маши новую бусы» → «новые бусы», «блестят роса» → «блестит роса»): из неверных окончаний, которые
  он расслышал, произнесённые отдельно (240 проверено, `iso.py`), во фразе «исправлено» каждое третье. Остальное —
  безударные слоги («медленну» ≈ «медленно»). Сверкой это не поправить.
- Ужесточение `wordTolerance` (0,25 → 0,20 → 0,15): замены слов 79 → 87 → 91%, окончания красным 14 → 22 → 36%, но
  ложные красные на правильной эталонной озвучке 0,27 → 0,45 → 0,85% (на живом детском голосе будет больше). Детям
  важнее видимый прогресс, поэтому допуск оставлен 0,25, окончания — мягкая подсказка (решение Фёдора 05.11:
  дообучение распознавания на ошибках окончаний пока не делаем, режим щадящий).
- По слогам Silero озвучивает неестественно («Ма, ма.»), цифра 2,6% условная — нужны живые записи.

## Адаптивная сложность

После каждой попытки считается темп WCPM: сколько слов прочитано верно за минуту, время от начала первого
до конца последнего слова по CTC-выравниванию. Считается и точность (`ReadingStats`). Засчитываются только
попытки, где текст дочитан хотя бы до 80%. Попытки пишутся в журнал чтеца `files/progress-<id>.tsv` (см. «Чтецы»), а уровень
каждый раз вычисляется из журнала заново (`AdaptiveLevel`), поэтому правила можно менять без миграций.

| Уровень | Слов в тексте | Цель темпа для перехода | Подсказки |
|---|---|---|---|
| L1–L2 | 3–4 | 15, 20 | слоги цветом, ударения |
| L3 | 5–8 | 25 | слоги цветом, ударения |
| L4 | 15–30 | 30 | слоги цветом, ударения |
| L5 | 35–60 | 40 | ударения |
| L6 | 50–70 | 50 | — |
| L7 | 80–110 | 65 | — |
| L8 | 120–160 | 80 | — |
| L9 | 170–230 | 95 → 120 | — |

Ориентир — нормы техники чтения к концу года: 1 кл. 30–40, 2 кл. 50–70, 3 кл. 70–90, 4 кл. 90–120 слов/мин.

* Повышение: 3 последние попытки на уровне с точностью от 95% и темпом не ниже цели.
* Понижение: 2 попытки подряд с точностью ниже 85%, текст слишком трудный.
* Вызов: каждый 5-й текст берётся на уровень выше. Неудача не понижает, а успех идёт в окно повышения.
* Тексты: сначала непрочитанные своего уровня, затем те, что читались давно.

## Чтецы: профили и опознание по голосу

Приложением пользуется вся семья, поэтому журнал, уровень и рекорд ведутся по каждому человеку отдельно.
Человек узнаётся по голосу на телефоне, без интернета и без вопросов. Ребёнку опознание нигде не показывается.

**Модель.** 3D-Speaker CAM++ `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` (Apache-2.0, 28 МБ,
эмбеддинг 192) из релиза sherpa-onnx `speaker-recongition-models`. Лежит в `files/`, как GigaAM, в APK не входит.
Считается на CPU в 2 потока. На S26 Ultra 13 с речи обрабатываются за 17 мс (признаки) + 44 мс (модель).
Признаки (`Fbank`) повторяют Kaldi fbank 80: окно povey, preemph 0.97, 25/10 мс, без dither, snip_edges.
Затем отбираются речевые кадры (энергия не ниже p95 − 30 дБ и не ниже −55 дБFS), вычитается среднее,
берётся не больше 30 с речи. С kaldi-native-fbank совпадает до 1e-4 (`FbankTest`).
Эмбеддинг на телефоне совпадает с Python: косинус 0,99999998.

Сравнение моделей (`ml/speaker_eval.py`) проведено на speechocean762 (OpenSLR 101). Это 80 детей 6–10 лет
и 128 взрослых, китайцы читают по-английски, фразы по 2–5 с. Число в колонке «семья» — доля верно
опознанных фраз, когда в семье 3 ребёнка и 2 взрослых, а профиль собран из 3 фраз.

| Модель | МБ | EER дети↔дети | EER взрослые | «Семья» | Скорость (r99950x, RTF) |
|---|---|---|---|---|---|
| **CAM++ zh_en advanced** | 28 | **4,3%** | 1,0% | 99,9% | 0,003 |
| ERes2NetV2 zh-cn | 71 | 3,2% | 0,8% | 100% | 0,010 |
| ERes2Net base | 40 | 5,2% | 1,9% | 99,7% | 0,005 |
| WeSpeaker ResNet34 | 27 | 6,5% | 1,6% | 99,8% | 0,003 |
| WeSpeaker CAM++ (VoxCeleb) | 29 | 10,4% | 2,2% | 99,2% | 0,003 |
| CAM++ VoxCeleb | 30 | 11,1% | 2,7% | 99,2% | 0,003 |

ERes2NetV2 немного точнее, но в 2,5 раза больше и в 3 раза медленнее. Модели, обученные только на VoxCeleb,
заметно хуже на детях.

**Решение после каждого чтения** (`SpeakerId`, пороги — константы, подобраны в `ml/speaker_tune.py`):

| Условие | Решение | Что происходит |
|---|---|---|
| речи меньше 0,8 с | SHORT | попытка в `progress-unknown.tsv` |
| лучший косинус ≥ 0,50 и отрыв от второго ≥ 0,12 | MATCH | попытка в `progress-<id>.tsv`, профиль дообучается |
| лучший косинус < 0,30, речи ≥ 2 с, попытка засчитана | NEW | новый профиль «Чтец N» |
| остальное | UNSURE | попытка в `progress-unknown.tsv`: в уровень не идёт и профиль не дообучает |

Когда профиль собран из 3 попыток, на speechocean762 получается так: свой опознан в 98%, к чужому
профилю 0%, ложный «новый» 0,1%, остальное «не определён». Незнакомец уходит в чужой профиль в 8% фраз.
Это короткие фразы. Чтение текста длиннее, поэтому на нём будет точнее.

Профиль хранит нормированное среднее эмбеддингов: первые 20 попыток — накопленное среднее, дальше
скользящее с весом 0,05 (голос ребёнка меняется). Ручная правка в родительском экране весит 0,2.

**Ребёнок или взрослый** определяется логистической регрессией по эмбеддингу (обучена на speechocean762,
89% по одной фразе на отложенных людях). P(ребёнок) ≥ 0,75 — ребёнок, ≤ 0,25 — взрослый, между — неизвестно.
На озвучке персонажей «девочка» и «мальчик» модель даёт 0,3 (это не дети), Фёдор получает 0,17.
Оценка грубая: стартовый уровень по ней — L7 для «взрослого по голосу» и L5 для остальных.
Если родитель указал «взрослый», старт с L9.

**Файлы:**
* `files/profiles/<id>.json` — имя, аватар, цвет, тип, `kid_p`, стартовый уровень, `n`, `emb`;
  `profiles/last.txt` — последний опознанный чтец;
* `files/progress-<id>.tsv`, `progress-unknown.tsv` — журналы. 7-й столбец — имя записи в `recordings/`;
* `files/recordings/<запись>.json` → `speaker`: решение, секунды речи, косинусы ко всем профилям, эмбеддинг.
  По ним попытки можно пересортировать. Новый профиль сразу забирает уверенно похожие «не определённые» попытки;
* старый общий `progress.tsv` не трогается. Без файла модели приложение работает с ним, как раньше.

**Экран.** Строка «Уровень · цель · рекорд» показывает последнего опознанного чтеца, без имени.
По его уровню выбирается следующий текст. Родительский экран открывается долгим нажатием на строку уровня.
В нём список чтецов (имя, ребёнок/взрослый, попытки, уровень, рекорд, объединение двух профилей одного человека)
и последние 40 попыток с косинусами. Нажатие на попытку позволяет её послушать или переложить другому чтецу,
в новый профиль или в «не определён».

**Логи:** `голос: признаки N мс, модель N мс; речь X с: p1(Чтец 1)=0.741 p2(Чтец 2)=0.055 → MATCH p1, P(ребёнок)=…`.

**Проверено на S26 Ultra** (без микрофона, через `--es wav`). Две записи «девочки» дали новый профиль и
совпадение 0,74. Живая запись Фёдора: косинус 0,06 к «девочке», завёлся новый профиль (взрослый, P 0,17).
Следующие записи Фёдора совпали с ним с косинусом 0,61 и 0,72. Короткая запись (1,4 с) дала 0,49 →
«не определён». «Мальчик» дал 0,35 к «девочке» → «не определён»: оба голоса получены через Seed-VC
из одного голоса Silero.

## Соревнования

Вход — небольшая кнопка-кубок справа в строке уровня на экране чтения (`CompeteActivity`: «Дуэль» и «Рекорды»).
Подсчёты — чистый `Leaderboard` в модуле `reading` (`LeaderboardTest`, 8 тестов), экраны — `DuelActivity`, `RecordsActivity`.

**Дуэль на одном тексте** (`DuelActivity`). Перед стартом выбирается уровень L1…L9 (по умолчанию уровень последнего
опознанного чтеца), текст случайный этого уровня, кнопка ▶ — другой текст. «Читает следующий» открывает обычный
`ReadActivity` с `duel=true` и `text_id`: та же подсветка и телесуфлёр; после чтения экран сам возвращается в дуэль
с результатом (`wcpm`, `accuracy`, `seconds`, `profile`). Кто читал — тихое опознание по голосу (`SpeakerId`,
`Profiles`): имя, аватар и цвет профиля; неопознанный — «Игрок N» с номером на сером кружке. Ребёнка ни о чём не
спрашивают; тап по строке таблицы — необязательная правка «кто читал». Таблица: место (у лидера 👑 и золотая рамка),
время, слов/мин, точность, **счёт = слов/мин × точность**; при повторном чтении одного человека берётся лучший раунд.
«Итоги» — победитель плашкой, конфетти, игровой звук; дуэль дописывается в `files/duels.jsonl` (победитель, строки).
Попытки идут в журналы как обычные (уровень — по журналу человека), в `recordings/*.json` отмечено `"duel": true`.

**Рекорды** (`RecordsActivity`) — все профили карточками: аватар, имя, ⭐ за каждый засчитанный текст сегодня,
🔥 серия дней подряд с чтением (держится до конца следующего дня), уровень, лучший темп (точность ≥ 95%),
прочитано всего и сегодня; сверху — победитель последней дуэли. Сортировка: серия, затем прочитано сегодня, затем всего.
«День» — календарный в часовом поясе телефона.

**Отладка без микрофона:** `am start -n dev.gubenkov.readbench/.DuelActivity --es text_id ru-L5-001 --es wavs a.wav,b.wav --ez auto true` —
раунды берут wav (16 кГц моно в `files/`) по очереди, как `--es wav` у `ReadActivity`. Проверено на S26 Ultra 04.11 на озвучке
«девочка» и «сказочник» текста ru-L5-001: два новых профиля, счёт 131 и 136, итоги и рекорды в светлой и тёмной теме.

## Награды и видимый прогресс

Детям важны уровни, прогресс и награды за улучшения (отзыв Вероники после первого вечера, 04.11). Награды
(`Achievements`, модуль `reading`) не хранятся: как и уровень, выводятся из журнала чтеца, поэтому заработанное
раньше появилось сразу, а правила можно менять.

Серии (ступени): 📖 прочитано текстов (1…200), ⚡ темп без ошибок (≥ 90% точности; 20…150 сл/мин),
🎯 уровни 2…9, 🚀 быстрее, чем в прошлый день чтения, 📈 знакомый текст быстрее на 15%+, 💎 без единой ошибки,
🏔 трудный текст (вызов) ≥ 95%, 🔥 дни подряд, 🏃 5/10 текстов за день. «Читательский» день начинается в 4:00:
вечер, перевалив за полночь, не даёт серию «2 дня».

Экран: строка уровня в две строки — «Уровень 7 · рекорд 91 · 🏅 21» и «До уровня 8: ещё 3 текста быстрее 65 сл/мин»
(`AdaptiveLevel.toNextLevel`). Тап по ней — «Награды» (`AwardsActivity`): аватары чтецов, заработанные плитки с датой
и в каждой серии следующая ступень серой с подсказкой. Новые награды всплывают после чтения карточкой сверху со
звуком (монетка, на уровень — фанфара). В «Рекордах» у чтеца 🏅 N, тап по карточке — его награды.

Окно повышения уровня — из разных текстов: повтор того же текста ради рекорда заменяет прошлую попытку в окне.

## В «Таблице» (этап 5)

Модуль `reading` — зависимость `app`. Экран блокировки остаётся одним (`QuizActivity`): по настройке родителя он
показывает примеры или `ReadingScreen` (вид внутри той же активности — службы блокировки и спецвозможностей не менялись).

**Выбор задания** (`TaskPicker`, чистая логика, JUnit). Настройка «Задание на экране блокировки»: примеры / чтение вслух /
вперемешку (по очереди: чётный сеанс — чтение, нечётный — примеры). Чтение дают, только если готово всё:
`texts.jsonl`, загружаемая без компиляции модель (CPU-файл или NPU с готовым контекстом) и разрешение на микрофон.
Экран родительского кода (защита Настроек) — всегда клавиатура.

**Разблокировка чтением**: один текст. Засчитывается, когда `ReadingMatcher` дал complete (все слова верно с перечитыванием
красных — по умолчанию, порог 100%), либо доля верных слов (с учётом перечитывания) не ниже порога родителя (50–100%).
Уровень текста — `AdaptiveLevel` по журналу последнего опознанного чтеца (`SpeakerId`, профили `ReaderProfiles` в том же
формате, что у readbench: `files/profiles/`, `progress-<id>.tsv`, `recordings/`). Без CAM++ — общий `progress.tsv`.
Стартовый уровень нового чтеца задаёт родитель (по умолчанию 5). Шумная неудача (была подсказка «шумно», точность < 85%)
в журнал не идёт.

**Экран**: строка «Уровень · рекорд · 🏅» и «До уровня N…», карточка текста (слоги цветом и ударения на младших уровнях,
подсветка верно/ошибка/текущее/окончание, телесуфлёр), «послушать» (только если есть `tts/<id>.*`), большой микрофон с
защитой от дребезга, автостоп после конца текста, подсказки «шумно»/«погромче», «Молодец!» со звуком, новые награды строкой —
и разблокировка через 2,4 с (3,8 с, если были награды). Без соревнований, «Новых слов» и родительских диалогов readbench.

**Откат на примеры — ребёнок не остаётся без способа разблокироваться:**

| Что случилось | Что видит ребёнок |
|---|---|
| нет пакета, модели, контекст NPU не собран, нет разрешения на микрофон | сразу примеры |
| модель не загрузилась, `AudioRecord` не открылся (микрофон занят), любое исключение экрана чтения | примеры с подсказкой |
| модель грузится дольше 30 с; 3 неудачных прочтения; 4 мин на экране | кнопка «Примеры» |
| экран погас посреди записи | запись не засчитывается, экран как был |
| долгое нажатие на строку уровня | примеры (там вводится родительский код) |

**Модели без интернета.** Пакет — папка: `texts.jsonl`, `gigaam3-ctc-ru.model.json`, `gigaam_ctc_T1600_qdq.onnx` (NPU),
`gigaam_ctc_int8.onnx` (CPU-запасной), CAM++ `3dspeaker_…onnx`, `tts/`. Собирает `ml/make_reading_pack.sh <модели> <tts|-> <выход>`
(fp32 — только с `PACK_FP32=1`). Три способа поставить:

1. Скопировать папку на телефон (кабелем в «Загрузки», флешкой OTG) → в настройках «Установить пакет чтения из папки…»
   (системный выбор папки; копируются только файлы пакета, через `.part` и переименование — журналы не трогаются).
2. Положить папку в `android/app/reading-pack/` (в git не входит) — пакет войдёт в APK (`assets/reading/`, без сжатия),
   кнопка «Установить пакет чтения из приложения». APK вырастет на размер моделей.
3. `adb push` в `Android/data/dev.gubenkov.mathlock/files/` (как у readbench).

Файлы лежат во внешних `files/` приложения (ребёнку недоступны без adb: Android/data закрыт, Настройки — под кодом).

**NPU** (`ReadingEngine`, `ReadingPack.plan`): порядок QDQ A16W8 (HTP v68/v69 без fp16 — Xiaomi 13 Lite; идёт и на новых) →
fp32 с fp16 (HTP v73+) → CPU int8 → CPU fp32. Компиляция графа под HTP — минуты, поэтому на экране блокировки её нет:
после установки пакета (или кнопкой «Подготовить модель для NPU») она идёт у родителя, контекст кэшируется во внутренних
`files/qnn/<модель>_qnnctx.onnx`. Пока контекста нет, экран блокировки берёт CPU int8. Перед созданием сессии QNN
кладётся метка `qnn/loading`; если процесс упал в нативном коде, при следующем старте метка находится → NPU помечается
сломанным, дальше CPU (снимает «Подготовить»). Битый или чужой (после обновления ORT) контекст удаляется. Новая модель
из пакета сбрасывает свой контекст. Модели держатся в памяти, пока открыт экран чтения, и выгружаются через минуту после.
APK «Таблицы» с ORT+QNN — около 74 МБ (GPU/DSP-бэкенды QNN не включены); вне arm64 чтение просто недоступно.

**Не проверено на телефоне** (по согласованию — без установки): весь экран, компиляция QDQ под v69 и её время, запись
с экрана блокировки поверх keyguard на HyperOS, выбор папки на Xiaomi.

## Ударения и интонация (план)

По выравниванию CTC находим отрезки гласных и считаем у каждой длительность, громкость и F0.
Ударную гласную определяет классификатор, обученный сначала на озвучке (ударение известно из текста), потом на записях ребёнка.
Интонацию проверяем по контуру F0 на последнем слове предложения (. ? !) в сравнении с эталонной озвучкой.
Результат идёт только в подсказку («послушай, как правильно») и не мешает разблокировке.
